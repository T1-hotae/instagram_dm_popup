# [03] 기술과 원리

InstaDM을 무엇으로 만들었고, 각 기능이 어떤 원리로 동작하는지 정리한다. 파일과 IPC 목록은 [00] 구조.md에, 새 DM 판정 규칙은 [02] 알림 구현 원리.md에 자세히 있다. 이 문서는 그 둘을 읽기 전에 전체 그림을 잡는 용도다.

## 한 줄 요약

Instagram 공식 웹을 그대로 띄운 **Electron 앱**이다. 화면은 Instagram이 그리고, 앱은 그 옆에서 **숨은 창 하나로 받은편지함을 계속 지켜보다가** 새 DM이 보이면 오른쪽 아래에 **직접 만든 팝업 창**을 띄운다. Instagram 서버에 따로 접속하는 코드는 없고, 로그인한 웹 페이지가 보는 것을 읽을 뿐이다.

## 쓴 기술

| 무엇 | 어디에 | 왜 |
|---|---|---|
| Electron 33 | 앱 전체 | Chromium으로 Instagram 웹을 그대로 띄우면서 트레이, 작업표시줄 배지, 항상 위 창 같은 Windows 기능을 쓸 수 있다 |
| `BrowserWindow` + `WebContentsView` | 메인 창 | 창 하나에 타이틀바 화면(`titlebar.html`)과 Instagram 화면(`igView`)을 위아래로 붙인다 |
| 세션 파티션 `persist:instagram` | 모든 Instagram 창 | 쿠키를 디스크에 남겨 로그인을 유지하고, 메인 창·감시 창·로그인 창이 같은 로그인 상태를 쓴다 |
| preload + `contextBridge` + IPC | 각 창 | 페이지와 Node 권한을 나눈 채(`contextIsolation`, `sandbox`) 필요한 함수만 열어 주고 메시지로 주고받는다 |
| `webFrame.executeJavaScript` | `instagram/`, `watcher/` preload | preload는 페이지와 다른 JS 세계에서 돈다. 페이지의 `Notification`이나 `document.hidden`을 바꾸려면 페이지 세계에 코드를 넣어야 한다 |
| `Tray`, `setOverlayIcon`, `flashFrame` | main.js | 트레이 아이콘·메뉴, 작업표시줄 빨간 점, 창 깜빡임 |
| Web Audio (`AudioContext`) | `popup.html` | 소리 파일 없이 짧은 두 음 알림음을 만든다 |
| electron-builder (NSIS) | `npm run dist` | Windows 설치 파일 `InstaDM-Setup-x.y.z.exe`를 만든다 |

외부 라이브러리는 Electron과 electron-builder 둘뿐이고, 화면도 프레임워크 없이 HTML·CSS·JS로 썼다.

## 기능별 원리

### 1. 로그인 유지와 "지원하지 않는 브라우저" 피하기
- 비밀번호는 앱이 다루지 않는다. 사용자가 Instagram 웹 화면에서 직접 로그인하고, 쿠키가 `persist:instagram`에 남는다.
- Electron 기본 User-Agent에는 `Electron/33...`이 붙어서 Instagram이 막을 수 있다. 시작할 때 이 부분을 지워 일반 Chrome처럼 보이게 한다(`app.userAgentFallback`).
- 페이스북·Meta 계정 로그인은 새 창을 요구한다. `setWindowOpenHandler`에서 이 주소만 같은 세션의 작은 창으로 열고, Instagram 링크는 메인 창에서, 나머지는 기본 브라우저로 연다.

### 2. 커스텀 타이틀바
- 메인 창을 `frame: false`로 만들어 Windows 기본 제목줄을 없애고, 창 자체에 36px짜리 `titlebar.html`을 그린다.
- 그 아래 영역에 `igView`를 붙이고, 창 크기가 바뀔 때마다 위치를 다시 맞춘다.
- 창 끌기는 CSS `-webkit-app-region: drag`, 버튼은 IPC(`titlebar:*`)로 처리한다.
- Instagram 화면 배경이 어두운지 5초마다 보고(`syncTheme`) 타이틀바 색을 맞춘다.

### 3. 새 DM 감지: 숨은 감시 창
메인 창은 사용자가 보거나 숨기거나 다른 대화방으로 옮겨 다니므로 감지용으로 믿을 수 없다. 그래서 **화면에 띄우지 않는 1280×900 창**을 따로 만들어 늘 받은편지함을 열어 둔다(`watcher/preload.js`). 폭을 넓게 잡는 이유는 대화 목록이 보이는 데스크톱 화면 구성이 나오게 하려는 것이다.

감시 창은 두 가지 방법을 순서대로 쓴다.

1. **받은편지함 데이터 읽기**: Instagram 웹이 목록을 그릴 때 부르는 `/api/v1/direct_v2/inbox/`를 같은 쿠키로 요청한다. 보낸 사람, 내용, 프로필 사진, 읽은 시각(`last_seen_at`)이 다 들어 있어서 가장 정확하다. 1분마다, 그리고 탭 제목 숫자가 오를 때만 요청하며, 401/403/429가 오면 10분 쉰다. 2026-10부터 404를 돌려주어 지금은 쓰이지 않는다.
2. **화면 목록 읽기**: 1.5초마다 대화 목록의 줄을 찾아 이름과 미리보기 글자를 읽는다. 미리보기 글씨가 굵으면(600 이상) 읽지 않은 것으로, 미리보기가 "입력 중"이면 입력 중으로 본다. 대화마다 마지막으로 알린 상태를 기억하고 **상태가 바뀔 때만** 알린다. 지금 실제로 알림을 만드는 곳이 여기다.

숨은 창이라 Chromium이 페이지를 "안 보임"으로 두면 목록 갱신이 늦어질 수 있다. 그래서 감시 창 안에서만 `document.hidden`을 늘 `false`로 보이게 하고, `backgroundThrottling: false`로 타이머가 느려지지 않게 한다.

시작할 때 이미 있던 읽지 않은 메시지는 기준으로만 삼고 알리지 않는다. 앱을 켤 때마다 예전 메시지가 팝업으로 쏟아지지 않게 하려는 것이다.

### 4. 페이지 알림 가로채기
Instagram 웹은 브라우저 알림(`new Notification(...)`, `showNotification`)을 쓴다. `instagram/preload.js`는 페이지의 `Notification`을 같은 모양의 가짜 클래스로 바꿔서, 알림이 생기면 Windows 알림 대신 메인 프로세스로 보낸다. 팝업을 누르면 원래 알림의 `onclick`을 실행해 Instagram이 그 대화로 이동하게 한다.

다만 이 알림에는 좋아요 같은 활동 알림이 섞이고 감시 창과 같은 DM을 겹쳐 알린다. 그래서 감시 창의 데이터 읽기가 잘 될 때는 버리고, 안 될 때만 주소에 `direct`가 있는 것을 통과시킨다.

### 5. 팝업
- 알림 하나마다 작은 `BrowserWindow`를 만든다. 테두리 없음, 투명, 항상 위, `focusable: false`라서 하던 작업의 포커스를 뺏지 않는다.
- 화면 작업 영역 오른쪽 아래부터 위로 최대 4개까지 쌓는다. 같은 대화(tag)의 팝업은 새 내용으로 교체한다. 그래서 "입력 중" 팝업이 실제 메시지 팝업으로 바뀐다.
- 프로필 사진은 팝업이 Instagram 이미지 서버에서 직접 받으면 막힐 수 있어서, 메인 프로세스가 로그인 세션으로 먼저 받아 data URL로 넘긴다(`resolveAvatar`, 100개까지 캐시).
- 5초 뒤 사라지고, 마우스를 올리면 멈춘다. 같은 `이름|내용`은 10초 안에 다시 띄우지 않는다(화면 읽기끼리는 제외). 메인 창을 보고 있을 때는 띄우지 않는다.

### 6. 읽지 않음 배지
- Instagram 탭 제목은 `(3) Instagram`처럼 숫자를 보여 준다. `MutationObserver`로 제목을 지켜보다가 숫자를 보낸다.
- 제목은 새 메시지가 오면 숫자와 "OO님이 메시지를 보냈습니다"를 번갈아 보여 주므로 숫자가 0↔1로 깜빡인다. 늘어날 때는 1.5초, 줄어들 때는 5초 동안 그대로여야 반영한다.
- 이 숫자로 트레이 툴팁, 작업표시줄 빨간 점(`badge.png` 오버레이), 타이틀바 알약을 갱신한다.

### 7. 트레이 상주
- 창의 X는 종료가 아니라 숨기기다. 앱은 트레이에 남고, 종료는 트레이 메뉴에서만 한다.
- 트레이 우클릭 메뉴와 타이틀바 ⋯ 메뉴는 같은 `menuTemplate()`에서 만든다.
- `requestSingleInstanceLock`으로 하나만 실행한다. 두 번째로 실행하면 기존 창을 앞으로 가져온다.
- "Windows 시작 시 실행"은 `setLoginItemSettings`에 `--hidden`을 붙여 등록해서, 부팅 때는 창 없이 트레이로만 뜬다.

### 8. 흰 화면과 멈춤 대비
- 숨김→표시, 최소화→복원 때 `igView` 위치를 다시 맞추고 `invalidate()`로 다시 그린다.
- 렌더러가 죽으면 1초 뒤, 불러오기에 실패하면 30초 뒤 다시 불러온다.
- 감시 창은 받은편지함을 벗어나면 1분 뒤 돌아오고, 메모리 누수를 막으려고 3시간마다 새로 불러온다. 절전에서 깨어나거나 잠금을 풀면 바로 다시 불러온다.

## 안전과 개인정보
- 모든 창이 `contextIsolation: true`, `sandbox: true`다. 페이지 코드는 Node나 파일에 손댈 수 없고, preload가 열어 준 몇 개 함수만 부를 수 있다.
- Instagram 밖 주소로 이동하려 하면 막고 기본 브라우저로 연다.
- 로그(`%APPDATA%\insta-dm\insta-dm.log`)와 진단 파일에는 상태, 개수, 경로만 남기고 메시지 내용·이름·프로필 주소는 남기지 않는다.
- 요청 빈도는 웹을 직접 쓸 때와 비슷하게 묶어 두었다(1분 주기, 오류 시 10분 휴식).

## 한계
- 공개 API가 아니라 Instagram 웹 내부 경로와 화면 구조에 기대므로 Instagram이 바꾸면 깨질 수 있다. 바뀌기 쉬운 지점은 [00] 구조.md의 "외부 의존"에 모아 두었다.
- 화면 읽기는 이름과 미리보기 글자만 알 수 있어서, 읽기 전에 같은 대화에 메시지가 연달아 오면 두 번째부터는 팝업이 없다.
- 앱이 꺼져 있거나 PC가 잠들어 있으면 알림이 오지 않는다(서버 푸시를 받지 않는다).
