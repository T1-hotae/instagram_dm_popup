# [02] 알림 구현 원리

새 DM 알림이 어떻게 감지되어 팝업까지 가는지 정리한다. 알림 관련 코드를 고치면 이 문서를 먼저 고친다. 창 구성과 IPC 전체 목록은 [00] 구조.md에 있다.

## 한눈에 보기

```
[감시 창 watcherWindow]  숨은 1280×900 창, 받은편지함만 띄워 둠
  watcher-preload.js
   ├─ ① checkInbox   받은편지함 데이터(API)          ── 현재 404, 사실상 꺼짐
   └─ ② scanDom      받은편지함 목록 화면을 1.5초마다 읽음 ── 지금 실제로 알림을 만드는 곳
          │ dm:notify {source:'dom'}
          ▼
[main.js] dm:notify → resolveAvatar → showPopup → popup.html (오른쪽 아래)

[igView] preload.js
   ├─ ③ Notification 가로채기  페이지가 직접 띄우는 알림  ── API가 안 될 때 DM 것만 통과
   └─ 탭 제목 "(N)"            배지 숫자, 감시 창에 즉시 확인 요청
```

## ① 받은편지함 데이터 (`checkInbox`, `processInbox`)

- `/api/v1/direct_v2/inbox/`를 로그인 세션으로 60초마다 요청한다. 제목 숫자가 오르면 바로 한 번 더 요청한다.
- 처음 읽은 내용은 기준으로만 삼고 알리지 않는다(`seededAtUs`). 내가 보낸 것, 시작 전에 온 것, `last_seen_at` 이전 것은 뺀다.
- 401/403/429면 10분 동안 멈춘다(계정 보호).
- **2026-10부터 404를 돌려준다.** 성공한 지 3분이 넘으면 `apiHealthy()`가 false가 되어 ②가 알림을 맡는다.

## ② 화면 읽기 (`scanDom`) — 지금의 주 경로

1. `rowCandidates()`로 목록의 대화 줄을 찾는다. `/direct/t/` 링크가 있거나, 높이가 44–120px이고 이미지가 있으며 글자가 두 줄 이상인 요소를 대화 줄로 본다.
2. `parseRow()`로 줄마다 다음을 읽는다.
   - `name`: 첫 줄
   - `preview`: 나머지 줄. 끝의 ` · 1분` 같은 시간 표시는 지운다.
   - `unread`: 미리보기 글자 굵기가 600 이상이면 읽지 않음
   - `icon`, `url`
3. 줄마다 **종류**를 정한다.

   | 종류 | 조건 | 팝업 본문 |
   |---|---|---|
   | `typing` | 미리보기가 `TYPING`(`/입력\s*중\|typing/i`)에 맞음. 굵기와 관계없음 | "입력 중…" (화면 글자 그대로) |
   | `msg` | 굵은 글씨이고 `MINE`(`나:`, `회원님:`, `You:`)으로 시작하지 않음 | 메시지 미리보기 |
   | 없음 | 그 밖(읽음, 내가 보낸 것) | — |

4. `notifiedRows`(대화 이름 → 마지막으로 알린 종류)와 비교해 **종류가 바뀔 때만** 알린다. 종류가 없어지면 기록을 지운다.

   예: 상대가 입력 → 보냄 → 다시 입력 → 보냄 → 내가 읽음
   ```
   preview      unread  kind    기록 전 → 후      팝업
   입력 중...     -      typing  없음 → typing      "입력 중..."
   안녕           굵게   msg     typing → msg       "안녕" (입력 중 팝업을 교체)
   안녕 · 1분     굵게   msg     msg → msg          없음 (시간 글자만 바뀜)
   입력 중...     -      typing  msg → typing       "입력 중..."
   뭐해           굵게   msg     typing → msg       "뭐해"
   뭐해           보통   없음    msg → 지움         없음
   ```
5. 처음 한 번 읽을 때(`domSeeded`)는 기록만 하고 알리지 않는다. 앱을 켰을 때 이미 있던 읽지 않음으로 팝업이 쏟아지지 않게 하려는 것이다.
6. `apiHealthy()`가 true면 ②는 알리지 않는다. 한 번에 최대 3개까지 보낸다.
7. `tag`는 `'dm:' + 이름`이다. 같은 대화의 팝업은 새 팝업으로 **교체**된다(`showPopup`).

### 알려진 한계
- 입력 중 없이 읽기 전에 메시지가 연달아 오면 두 번째부터는 종류가 그대로 `msg`라 팝업이 없다. 미리보기 글자로 비교하면 시간 글자 때문에 매분 다시 알리는 문제(10-30)가 생겨 쓰지 않았다.
- 입력 중 문구는 글자로만 알아본다. Instagram 문구가 바뀌면 `TYPING`을 고친다.
- 이름이 같은 대화 둘은 구분하지 못한다.

## ③ 페이지 알림 (`preload.js`)

- `window.Notification`과 `ServiceWorkerRegistration.showNotification`을 바꿔 끼워 `dm:notify`(source 없음 = `page`)로 보낸다.
- main은 API가 정상이면 버리고(중복 방지), 아니면 `url`이나 `tag`에 `direct`가 있을 때만 통과시킨다(좋아요 같은 활동 알림 제외).

## main.js에서 팝업까지

- `dm:notify` → 로그 `알림 {source, hasBody, hasIcon}`(내용은 남기지 않음) → `resolveAvatar`로 프로필 사진을 data URL로 받음 → `showPopup`
- `showPopup`이 팝업을 띄우지 않는 경우
  - 설정에서 알림이 꺼져 있을 때
  - 메인 창이 보이고 포커스가 있을 때(보고 있으면 Instagram이 바로 읽음 처리하므로 알릴 필요가 없다)
  - 같은 `제목|내용`을 10초 안에 다시 보낼 때
- 팝업은 최대 4개까지 쌓이고 5초 뒤 사라진다. 누르면 그 대화를 연다.

## 주의할 점 (지난 실수)

- **창 가림 계산(`CalculateNativeWinOcclusion`)을 끄지 않는다.** 끄면 가려진 창에서도 Instagram 페이지가 `visible`이 되어, 열려 있는 대화방 메시지가 바로 읽음 처리될 수 있다.
- 미리보기 글자 전체를 "이미 알렸는지" 판단 기준으로 쓰지 않는다. 시간 글자가 매분 바뀐다(10-30).
- 증상을 들으면 대화방 화면 문제인지 팝업 문제인지 먼저 가린다. 11-03에 "입력 중만 뜨고 메시지가 안 뜸"을 대화방 화면 문제로 잘못 읽고 엉뚱한 곳을 두 번 고쳤다.

## 확인 방법

- 로그(`%APPDATA%\insta-dm\insta-dm.log`)
  - `감시 {"source":"dom", … "rows":8, "unreadRows":1}`: 화면 읽기가 줄을 찾았는지, 읽지 않음이 몇 개인지
  - `알림 {"source":"dom"}`: 팝업을 요청했는지
  - `감시 {"source":"api", "httpStatus":404}`: ①이 꺼져 있는지
- 트레이 → **알림 경로 점검**: 데이터·화면 읽기·프로필 사진이 각각 되는지
- 트레이 → **감시 창 보기**: 감시 창이 받은편지함을 제대로 띄우고 있는지
- 트레이 → **문제 진단 파일 저장**: 목록 줄 DOM 구조(글자 수와 굵기만, 내용 없음)
