- **수정**
  - `notifiedRows`를 대화 이름 → 종류(`typing`/`msg`) Map으로 바꿨다. 종류가 바뀔 때만 알린다. 입력 중 팝업 뒤 실제 메시지가 오면 메시지 팝업으로 교체된다(같은 tag).

  - 트레이와 ⋯ 메뉴에 `버전 x.y.z`, 트레이 툴팁에 버전을 표시한다. 버전은 1.0.3.
  - 알림 원리 문서 `[02] 알림 구현 원리.md`를 만들었다. AGENTS.md의 알림 규칙에 "입력 중"을 넣었다.

### 1. 대화방에서 메시지가 안 보이고 "입력 중"만 보임
- **증상**: 대화방을 열면 메시지가 하나만 보이다가 아예 안 보인다. 상대의 "입력 중" 표시는 뜬다.
- **원인 추정**: "입력 중"은 실시간 연결로 바로 그려지지만, 메시지 목록은 화면에 보이는 부분만 그리는 목록이라 페이지가 "안 보임" 상태로 판단하면 그리지 않는다. Windows의 창 가림 계산(Native Window Occlusion)이 숨김→표시나 최소화→복원 뒤에도 igView를 가려진 것으로 두는 경우가 있고, igView는 백그라운드 절전(`backgroundThrottling`)도 켜져 있었다. 11-01의 흰 화면도 같은 원인일 수 있다.
- **수정** (`main.js`) — 이 수정은 증상을 잘못 읽은 것이었고 11-04에 되돌렸다.
  - `app.commandLine.appendSwitch('disable-features', 'CalculateNativeWinOcclusion')`
  - igView에 `backgroundThrottling: false`
  - `메인 표시` 로그에 페이지의 `document.visibilityState`를 붙였다.
- **확인**: 트레이 → 종료 후 다시 실행. 숨겼다 띄우거나 최소화→복원 뒤 대화방을 열어 메시지가 보이는지 본다. 로그의 `메인 표시 … visible`인지 확인한다.
- **남은 문제**: 실제 대화방 DOM은 보지 않고 추정으로 고쳤다. 그래도 안 보이면 창 크기를 바꿔 보기, Ctrl+R로 돌아오는지 확인해 다음 원인(배치/페이지 자체 문제)을 좁힌다.

### 5. 읽지 않은 같은 대화를 1분마다 다시 알림
- **증상**: 읽지 않은 대화 하나가 1분 간격(매분 :12)으로 계속 팝업됐다.
- **원인**: 화면 읽기가 `이름|미리보기`로 이미 알렸는지 판단했다. 미리보기 옆 시간("1분" → "2분")이 매분 바뀌어 새 메시지로 취급됐다.
- **수정**: 대화(이름)마다 **읽지 않은 동안 한 번만** 알린다. 읽음으로 바뀌면 기록을 지워 다음 새 메시지 때 다시 알린다. 같은 대화에 읽기 전에 메시지가 더 와도 추가 팝업은 없다. 제목 숫자만 오를 때 맨 위 대화를 알리던 규칙도 지웠다. (`watcher-preload.js` `scanDom`)

### 1. 다 읽었는데 알림이 계속 뜸 / "읽지 않은 메시지·알림이 0개 있어요" 팝업
- **원인**
  - 새 메시지가 있으면 Instagram이 탭 제목을 `(1) Instagram` ↔ `OO님이 메시지를 보냈습니다`처럼 깜빡인다. 앱은 이걸 0→1 "증가"로 몇 초마다 받았다(로그에 `읽지 않음 증가 0 → 1`이 수 초 간격으로 반복됨).
  - 증가할 때마다 6초 뒤 요약 팝업이 예약됐고, 팝업 문구에는 **그 시점의** 숫자(대개 0)를 넣었다. 그래서 "0개" 팝업이 떴다.
  - 받은편지함 데이터 경로가 404를 돌려줘서(감시가 계속 실패) 요약 팝업이 막히지 않았다.
  - 화면 읽기 대체 경로는 숫자만 오르면 **읽은 줄이라도** 맨 위 대화를 알렸다.
- **수정**
  - 제목 기반 요약 팝업을 삭제했다. 제목 숫자는 배지 표시와 즉시 확인 신호로만 쓴다. (`main.js` `dm:unread`)
  - 제목 숫자 디바운스: 증가는 1.5초 뒤, 감소는 5초간 그대로일 때만 반영한다.
  - 화면 읽기: 굵은 글씨(읽지 않음)인 줄만 알린다. (`watcher-preload.js` `scanDom`)
  - API 판정을 강화했다. 시작 시점보다 오래된 메시지(예전 대화가 목록 위로 올라온 경우)와 `viewerId`를 모를 때는 알리지 않는다. viewer id는 `pk / pk_id / strong_id__ / thread.viewer_id` 순으로 찾는다.
  - 페이지 Notification은 API가 정상이면 버리고(중복·활동 알림 방지), 아닐 때는 `direct` 관련 알림만 통과시킨다.
  - 배지 숫자는 API가 정상이면 DM만 센 숫자(`dm:unread-api`)를 쓴다.
  - 작업표시줄 깜빡임은 제목 숫자가 아니라 실제 DM 알림이 있을 때만 한다.

### 2. 받은편지함 목록에서 프로필 사진을 누르면 스토리가 열림
- **수정**: `preload.js`가 캡처 단계에서 목록 줄 안 사진 클릭(`img`, `canvas` 스토리 링, `/stories/` 링크)을 가로채 그 대화를 연다. 대화방 헤더처럼 목록이 아닌 곳은 그대로 둔다(같은 위치·폭의 줄이 2개 이상 있어야 목록으로 판단).
- **안전망**: 가로채지 못해 1.5초 안에 `/stories/`로 이동하면 `main.js`가 뒤로 가기를 한다.

### 3. 로그인이 잘 안 됨
- **앱 쪽 원인과 수정**
  - 페이스북·Meta 로그인 팝업이 기본 브라우저로 열려 앱 세션에 반영되지 않았다. 이제 앱 안의 작은 창(같은 세션)에서 연다.
  - `meta.com`(`accountscenter.meta.com`, `auth.meta.com`) 2단계 인증 흐름이 외부로 빠졌다. 허용 목록에 추가했다.
  - 감시 창이 로그인 화면에서 60초마다 다시 불러오는 타이머가 겹쳐 쌓였다. 이제 타이머는 하나만 두고, 로그인 화면에서는 다시 불러오지 않으며 API도 요청하지 않는다.
- **Instagram 쪽 요인(앱에서 해결 불가)**: 새 기기 보안 확인, 자동화 탐지, Electron Client Hints 불일치. 로그에 `메인 이동 /accounts/...`, `/challenge` 경로가 남으니 그걸로 확인한다.
