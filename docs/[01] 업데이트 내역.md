## 2026-11-01

### 1. 메인 창이 흰 화면만 보임
- **수정** (`main.js` `createMainWindow`, 아래 계획의 1~3)
  - `show`, `restore`, `maximize`, `unmaximize`에서 `layoutView()`와 `wc.invalidate()`를 부른다.
  - `render-process-gone` → 로그(`메인 렌더러 종료` 이유, 종료 코드) 후 1초 뒤 `reload`. `unresponsive`/`responsive` → 로그.
  - `did-fail-load`(메인 프레임, `-3` 제외) → 로그(`메인 불러오기 실패` 코드) 후 30초 뒤 `reload`. 오프라인일 때 요청이 몰리지 않게 간격을 넉넉히 뒀다.
  - `show` 때 `메인 표시 x,y 폭x높이`를 로그에 남긴다.
- **확인**: 트레이로 숨겼다 다시 띄우기, 최소화→복원을 반복해 흰 화면이 나오는지 본다. 재현되면 로그의 `메인 표시` 크기와 `메인 렌더러 종료`/`메인 불러오기 실패`가 있는지 본다. 그래도 남으면 계획 4(뷰 다시 붙이기)를 한다.

아래는 수정 전 분석이다.
- **증상**: 타이틀바(InstaDM, 배지 1)는 정상인데 아래 Instagram 영역이 통째로 하얗다. 왼쪽 끝에 파란 점 몇 개만 보인다.
- **로그로 확인한 것**
  - 배지 숫자는 `preload.js`(igView)가 탭 제목을 읽어 `dm:unread`로 보낸 값이다. 23:42에도 `읽지 않음 증가 0 → 1`이 찍혔으니 **igView 페이지는 살아서 JS가 돌고 있었다.** 렌더러가 죽은 경우는 아니다.
  - 감시 창은 계속 정상(`rows: 8`)이고, 같은 세션이라 로그인이 풀린 경우도 아니다.
  - igView에는 `render-process-gone`, `unresponsive`, `did-fail-load` 처리와 로그가 없다. 그래서 로그만으로는 무슨 일이 있었는지 더 좁힐 수 없다.
- **원인 추정** (가능성 높은 순)
  1. **창을 숨겼다 다시 띄울 때 igView가 다시 그려지지 않음.** X는 `hide()`, 트레이·팝업 클릭은 `show()`인데, Windows의 Electron `WebContentsView`는 숨김→표시나 최소화→복원 뒤 흰 화면으로 남는 경우가 있다. `layoutView()`는 `resize`에서만 돌고 `show`·`restore`에서는 돌지 않는다.
  2. **igView 크기·위치가 틀어짐.** `getContentSize()`가 숨김 상태에서 이상한 값을 주면 igView가 0폭이나 화면 밖으로 놓일 수 있다. 왼쪽 끝 파란 점은 이 경우와도 맞는다.
  3. Instagram 페이지가 자체적으로 빈 화면(SPA 오류)에 머묾. 그래도 제목 갱신은 계속된다.
- **구분 방법** (다음에 재현되면 순서대로 해 본다)
  - 창 크기를 조금 바꾸면 돌아오나 → 1 또는 2 (다시 그리기/배치 문제)
  - 최소화 후 복원하면 돌아오나 → 1
  - Ctrl+R로 돌아오나 → 3 (Ctrl+R로만 돌아오면 3)
  - Ctrl+Shift+I 개발자 도구에서 DOM이 비어 있나, 있는데 안 보이나
- **수정 계획** (`main.js` `createMainWindow`만 고친다)
  1. `mainWindow`의 `show`, `restore`, `maximize`, `unmaximize`에서도 `layoutView()`를 부르고 `wc.invalidate()`로 다시 그리게 한다.
  2. igView에 `render-process-gone`(이유만 로그, 그 뒤 `reload`), `unresponsive`(로그), `did-fail-load`(오류 코드만 로그, `-3` 취소는 무시, 그 외는 몇 초 뒤 `reload`)를 단다.
  3. `show`할 때 igView 크기를 로그에 남긴다(숫자만). 다음 재현 때 원인 2인지 바로 보인다.
  4. 1~3으로 안 고쳐지면: 다시 띄울 때 igView를 `removeChildView`→`addChildView`로 다시 붙인다.
- **남은 문제**: 재현 조건(숨김 뒤인지, 절전 복귀 뒤인지, 몇 시간 뒤인지)을 아직 모른다.

## 2026-10-30

### 5. 읽지 않은 같은 대화를 1분마다 다시 알림
- **증상**: 읽지 않은 대화 하나가 1분 간격(매분 :12)으로 계속 팝업됐다.
- **원인**: 화면 읽기가 `이름|미리보기`로 이미 알렸는지 판단했다. 미리보기 옆 시간("1분" → "2분")이 매분 바뀌어 새 메시지로 취급됐다.
- **수정**: 대화(이름)마다 **읽지 않은 동안 한 번만** 알린다. 읽음으로 바뀌면 기록을 지워 다음 새 메시지 때 다시 알린다. 같은 대화에 읽기 전에 메시지가 더 와도 추가 팝업은 없다. 제목 숫자만 오를 때 맨 위 대화를 알리던 규칙도 지웠다. (`watcher-preload.js` `scanDom`)

### 1. 다 읽었는데 알림이 계속 뜸 / "읽지 않은 메시지·알림이 0개 있어요" 팝업
- **원인**
  - 새 메시지가 있으면 Instagram이 탭 제목을 `(1) Instagram` ↔ `OO님이 메시지를 보냈습니다`처럼 깜빡인다. 앱은 이걸 0→1 "증가"로 몇 초마다 받았다(로그에 `읽지 않음 증가 0 → 1`이 수 초 간격으로 반복됨).
  - 증가할 때마다 6초 뒤 요약 팝업이 예약됐고, 팝업 문구에는 **그 시점의** 숫자(대개 0)를 넣었다. 그래서 "0개" 팝업이 떴다.
  - 받은편지함 데이터 경로가 404를 돌려줘서(감시가 계속 실패) 요약 팝업이 막히지 않았다.
  - 화면 읽기 대체 경로는 숫자만 오르면 **읽은 줄이라도** 맨 위 대화를 알렸다.
- **수정**
  - 제목 기반 요약 팝업을 삭제했다. 제목 숫자는 배지 표시와 즉시 확인 신호로만 쓴다. (`main.js` `dm:unread`)
  - 제목 숫자 디바운스: 증가는 1.5초 뒤, 감소는 5초간 그대로일 때만 반영한다.
  - 화면 읽기: 굵은 글씨(읽지 않음)인 줄만 알린다. (`watcher-preload.js` `scanDom`)
  - API 판정을 강화했다. 시작 시점보다 오래된 메시지(예전 대화가 목록 위로 올라온 경우)와 `viewerId`를 모를 때는 알리지 않는다. viewer id는 `pk / pk_id / strong_id__ / thread.viewer_id` 순으로 찾는다.
  - 페이지 Notification은 API가 정상이면 버리고(중복·활동 알림 방지), 아닐 때는 `direct` 관련 알림만 통과시킨다.
  - 배지 숫자는 API가 정상이면 DM만 센 숫자(`dm:unread-api`)를 쓴다.
  - 작업표시줄 깜빡임은 제목 숫자가 아니라 실제 DM 알림이 있을 때만 한다.

### 2. 받은편지함 목록에서 프로필 사진을 누르면 스토리가 열림
- **수정**: `preload.js`가 캡처 단계에서 목록 줄 안 사진 클릭(`img`, `canvas` 스토리 링, `/stories/` 링크)을 가로채 그 대화를 연다. 대화방 헤더처럼 목록이 아닌 곳은 그대로 둔다(같은 위치·폭의 줄이 2개 이상 있어야 목록으로 판단).
- **안전망**: 가로채지 못해 1.5초 안에 `/stories/`로 이동하면 `main.js`가 뒤로 가기를 한다.

### 3. 로그인이 잘 안 됨
- **앱 쪽 원인과 수정**
  - 페이스북·Meta 로그인 팝업이 기본 브라우저로 열려 앱 세션에 반영되지 않았다. 이제 앱 안의 작은 창(같은 세션)에서 연다.
  - `meta.com`(`accountscenter.meta.com`, `auth.meta.com`) 2단계 인증 흐름이 외부로 빠졌다. 허용 목록에 추가했다.
  - 감시 창이 로그인 화면에서 60초마다 다시 불러오는 타이머가 겹쳐 쌓였다. 이제 타이머는 하나만 두고, 로그인 화면에서는 다시 불러오지 않으며 API도 요청하지 않는다.
- **Instagram 쪽 요인(앱에서 해결 불가)**: 새 기기 보안 확인, 자동화 탐지, Electron Client Hints 불일치. 로그에 `메인 이동 /accounts/...`, `/challenge` 경로가 남으니 그걸로 확인한다.

### 4. 커스텀 타이틀바
- 메인 창을 테두리 없이 만들고 `titlebar.html`(36px)을 그렸다. Instagram은 `WebContentsView`(`igView`)로 그 아래에 붙인다.
- 구성: 앱 아이콘, InstaDM, 읽지 않음 알약(Instagram 그라데이션), ⋯ 설정 메뉴, 최소화, 최대화·복원, 닫기(빨간 hover).
- 읽지 않은 DM이 있으면 아래 경계선이 그라데이션으로 바뀐다. Instagram의 다크/라이트에 맞춰 색이 바뀌고, 창이 비활성이면 흐려진다.
- 앱 메뉴바(설정/보기)는 없앴다. 같은 메뉴를 ⋯ 버튼으로 열고, 단축키(Ctrl+R, Ctrl+= / - / 0, Ctrl+Shift+I)는 직접 처리한다.
- 제약: 최대화 버튼 hover 시 Windows 11 스냅 레이아웃 메뉴가 나오지 않는다(Win+Z, 끌어서 스냅은 됨).
